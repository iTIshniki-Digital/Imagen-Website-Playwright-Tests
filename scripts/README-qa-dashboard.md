# QA — запуск тестов и результаты через GitHub

Запуск и данные — целиком через GitHub API (не сторонний бэкенд). Сама
страница приложения хостится на Cloudflare Pages, а не на GitHub Pages
— бесплатный план организации не даёт приватные GitHub Pages, см.
`docs/README-setup.md` за подробностями. Форма на сайте
(wordpress-plugin/) и дашборд на claude.ai из этой схемы выведены
(подробности в самом низу).

## Основной способ — веб-приложение (Cloudflare Pages)

Адрес — тот, что получился на шаге 1 `docs/README-setup.md` (вида
`https://imagen-qa-runs.pages.dev`); сами подставьте, если ещё не
настраивали — после настройки имеет смысл дописать сюда готовую ссылку.

Настоящее веб-приложение: вход через GitHub, форма запуска, прогресс,
результаты по категориям, баги, история — одна страница. Исходники —
`docs/index.html` + `docs/app.js`. Разовая настройка (Cloudflare Pages,
OAuth App, Cloudflare Worker, Drive API-ключ) — **`docs/README-setup.md`**,
это отдельная инструкция, начните с неё.

## Запасной способ — GitHub Issue Form (без настройки, работает всегда)

Если приложение выше ещё не настроено или просто неудобно открывать:

1. **Issues → New issue → шаблон "QA test run"** — форма с чекбоксами
   браузеров/категорий (ничего не отмечено = полный набор), полем
   фильтра, полем cookies. Описание шаблона —
   `.github/ISSUE_TEMPLATE/qa-run.yml`.
2. Submit new issue.
3. `.github/workflows/qa-issue-trigger.yml` ловит открытие issue,
   `.github/scripts/handle-qa-run-issue.js` разбирает ответы формы (тот
   же белый список браузеров/путей/фильтра, что везде) и запускает
   `playwright.yml`. Если что-то не так — комментирует issue причиной,
   ничего не падает молча.

## Что происходит после запуска (общее для обоих способов)

Один скрипт, один проход — `scripts/publish-qa-dashboard-run.js` (шаг
"Publish run (Drive + GitHub Issues)" в `playwright.yml`). Раньше это
было два отдельных скрипта с раздельным парсингом отчёта — из-за этого
issues заводились без скриншотов (один скрипт их грузил на Drive, другой
про это не знал); нашли и объединили 2026-10-19. По завершении прогона
скрипт:
- грузит скриншоты и видео упавших проверок на Google Drive — один раз,
  дальше использует эти же ссылки везде ниже;
- заводит/обновляет issue с лейблом `qa-bug` на каждую упавшую проверку
  (скриншот и видео — прямо в теле issue); когда проверка снова проходит
  — закрывает issue автоматически с комментарием "Fixed";
- если запуск был через issue — комментирует туда итог и закрывает его;
- пишет сводку по категориям прямо на страницу прогона (Job Summary,
  вкладка Actions → этот прогон);
- публикует `latest.json` на Google Drive — это читает вкладка "Latest
  Run" веб-приложения.

## 0. Права записи для GitHub Actions (обязательно, один раз)

Оба workflow заводят/комментируют/закрывают issues и один из них
запускает другой — для этого токену нужны права на запись.

Сейчас это решено через **personal access token в секрете
`QA_BOT_TOKEN`** (создан 2026-10-14) — обходит нехватку админских прав
на репозиторий/организацию:

- PAT создан в личных настройках аккаунта
  (`https://github.com/settings/tokens/new`, scope `repo`) —
  это НЕ требует роли Admin на репозитории.
- Положен как обычный repository secret: Settings → Secrets and
  variables → Actions → `QA_BOT_TOKEN`.
- Оба workflow сначала пробуют его, и только если не задан — встроенный
  `GITHUB_TOKEN` (`secrets.QA_BOT_TOKEN || secrets.GITHUB_TOKEN`).

Если токен истечёт — Actions начнёт падать на шагах с issues с ошибкой
авторизации; чинится так же — новый PAT, обновить значение секрета.

(Альтернатива, если когда-нибудь появится Admin/Owner доступ: Repository
→ Settings → Actions → General → Workflow permissions → "Read and write
permissions" → Save, и тогда секрет `QA_BOT_TOKEN` можно удалить —
фолбэк на встроенный токен сработает сам.)

## 1. Создать фиксированный файл latest.json на Drive

Нужно и веб-приложению (вкладка "Latest Run"), и — опционально — старому
дашборду на claude.ai. Issue Form/issues работают без этого файла.

1. Откройте ту же папку Google Drive, куда уже падают отчёты (куда
   указывает секрет `GDRIVE_FOLDER_ID` в GitHub).
2. Создайте в ней пустой файл с содержимым `{}`, назовите `latest.json`.
3. Скопируйте его id из адресной строки:
   `https://drive.google.com/file/d/`**`ВОТ_ЭТОТ_ID`**`/view`.
4. GitHub → репозиторий → Settings → Secrets and variables → Actions →
   New repository secret → имя `GDRIVE_LATEST_JSON_FILE_ID`, значение —
   этот id.
5. Тот же id нужен в Cloudflare Worker (переменная
   `DRIVE_LATEST_JSON_FILE_ID`) — см. `docs/README-setup.md`, шаг 3. Он
   же сам умеет самовосстанавливаться, если изначально указан на файл,
   созданный не тем же Google-аккаунтом (пересоздаёт и громко просит
   обновить id — см. `uploadFailureMedia`/`publishLatestJson` в
   `scripts/publish-qa-dashboard-run.js`, живой случай был 2026-10-19).

Отдельно — секрет **`GDRIVE_API_KEY`** (тот же ключ, что
`DRIVE_API_KEY` в Worker'е, см. `docs/README-setup.md` шаг 4) — без него
скриншоты в issues и в "Latest Run" не прикладываются вообще (находка
2026-10-19: прямые ссылки `drive.google.com/uc?export=view` иногда не
отдают картинку браузеру с активной Google-сессией, только через API с
ключом — надёжно).

## 2. Отчёт в Slack после каждого прогона (необязательно)

1. https://api.slack.com/apps → **Create New App** → "From scratch" →
   выбрать свой workspace.
2. В настройках приложения слева → **Incoming Webhooks** → включить →
   **Add New Webhook to Workspace** → выбрать канал.
3. Скопировать URL вида `https://hooks.slack.com/services/...`.
4. GitHub → Settings → Secrets and variables → Actions → New repository
   secret → имя `SLACK_WEBHOOK_URL`, значение — этот URL.

Без этого секрета просто ничего не шлётся в Slack, остальной пайплайн не
страдает. Сообщение уходит после каждого прогона (не только при
падениях) — сводка по категориям, ссылка на полный отчёт и на сам
прогон в Actions.

## 3. Проверка переводов на смысл (необязательно, платно по чуть-чуть)

`tests/translation-review.spec.ts` — пункт чек-листа #13 ("Translation
review"), раньше чисто ручной. Title страницы и текст hero-кнопки на
каждой из 7 нелокальных локалей отправляются вместе с английским
оригиналом в Claude (модель `claude-haiku-4-5-20251001`, дёшево и быстро
— один запрос на локаль), модель проверяет, не потерян ли смысл и не
остался ли текст непереведённым. Не придирается к стилю или длине
заголовков (сокращают их для SEO специально — это нормально).

1. https://console.anthropic.com/ → Billing → купить минимальный пакет
   кредитов (стоимость самой проверки — доли цента за прогон).
2. **Settings → API Keys** → Create Key → срок действия **без
   ограничения** или максимально долгий (это для автоматики, не для
   человека — короткий срок тихо сломает проверку через месяц).
3. GitHub → Settings → Secrets and variables → Actions → New repository
   secret → имя `ANTHROPIC_API_KEY`, значение — этот ключ.

Без секрета тест аккуратно помечается skipped, ничего не падает. Гоняется
только в Chromium (текст не меняется от браузера к браузеру — незачем
платить трижды за одно и то же).

## Поддерживать категории в соответствии

Категории — категории ручного чек-листа клиента (дашборд
`marketing-server/services/qa-dashboard`), слово в слово. Список должен
совпадать в ПЯТИ местах — поменяли один, поменяйте все:
- `scripts/qa-dashboard-categories.js`
- `docs/app.js` (константа `CATEGORIES`)
- `.github/ISSUE_TEMPLATE/qa-run.yml` (чекбоксы "What to check")
- `wordpress-plugin/imagen-qa-test-runner.php` (`imagen_qa_scopes`,
  сейчас не используется для запуска, но держим на всякий случай)
- бывший claude.ai дашборд (не актуально, он выведен из процесса)
